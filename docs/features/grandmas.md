# Grandmas, recipes, and voice

## 1. Feature overview

Admins manage grandma profiles, recipes, voice messages, and the single grandma of the month.

## 2. Scope

In: admin CRUD listed below. Out: grandma login.

## 3. User roles

Admin with `grandmas`. Public reads are the catalog feature.

## 4. Permissions

`grandmas`.

## 5. Business rules

Status is `pending`, `active`, or `unavailable`. Unavailable grandmas reject new orders. Existing orders continue. Exactly one `is_grandma_of_month`. Voice `uuid` is generated by the server.

Normative detail: [BUSINESS_LOGIC.md](../product/BUSINESS_LOGIC.md) and [STATE_MACHINES.md](../architecture/STATE_MACHINES.md).

## 6. User workflows

Create grandma, add recipes and voice messages, mark grandma of the month.

## 7. Related entities

Grandma, Recipe, VoiceMessage.

## 8. Related endpoints

Admin routes under `/admin/grandmas` and `/admin/recipes` and `/admin/voice-messages` from the endpoint list.

Paths are listed in [API_ENDPOINTS.md](../api/API_ENDPOINTS.md). Field shapes follow [swagger.yaml](../api/swagger.yaml).

## 9. Validation

Name required. Order hours are optional times. Audio is stored as a URL produced by the storage port.

## 10. Security requirements

`admin_phone` is admin-only. Public QR cannot enumerate integer ids.

Also apply [SECURITY.md](../engineering/SECURITY.md).

## 11. Performance considerations

Unique partial index for grandma of the month.

## 12. Background jobs

None.

## 13. Edge cases

Setting a new grandma of the month clears the previous flag in the same transaction.

## 14. Failure scenarios

Deleting a recipe that is only text is allowed. Deleting a grandma with products returns 409.

## 15. Acceptance criteria

Public pages omit admin phone. One grandma of the month is enforced by the database.

## 16. Testing requirements

Integration: unique grandma of the month. Permission 403 without `grandmas`.

Definition of done: [TESTING_STRATEGY.md](../engineering/TESTING_STRATEGY.md).

## 19. Known limitations
